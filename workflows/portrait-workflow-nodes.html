人像美化工作流 · 节点说明

影视剧人物年轻化项目 · 32 节点工作流 · 9 个关键节点逐项拆解

这套工作流解决的问题是：把"年轻化"从一次性调参，变成一条可控、可批量、可交接的视频处理链路。 下面按数据流顺序记录每个关键节点的作用与调参口径，也是交给同事复用时依据的说明。

一、批处理与视频输入

1. 批次管理（Batch Manager）

VHS_BatchManager

把一组帧按批次分批送入模型处理，避免一次送太多帧导致爆显存。核心参数是每批次帧数（Frames per Batch）：数值越小显存压力越小、耗时越长；数值越大处理越快、但可能爆显存。

2. 加载视频（Load Video）

VHS_LoadVideo

"视频生视频"或"图生视频"的起点：把本地视频拆成帧，并按需要重采样、裁剪，再交给后续扩散模型处理。

3. 拆解批次（Unbatch）

VHS_Unbatch

把一批图像拆成单独的一张张图像，方便逐帧处理或预览。输入端口为批次（batch），输出端口为图像（image）。

4. 视频信息（Video Info）

VHS_VideoInfo

把一段视频的全部元数据一次性打包输出，供后续节点按需调用：原尺寸、帧率、时长、裁剪后还剩多少帧。

二、文本条件控制

5. 设置 CLIP 最后一层

CLIPSetLastLayer

强制让 CLIP 文本编码器提前在某一层"截断"，从而改变 prompt 对扩散模型的影响力与风格。

参数含义常用值备注
停止在 CLIP 层最终保留到第几层-20、-10、-1、-2 负数 = 从最后一层倒数；-1 即官方默认（完整 12 层）；数值负得越多截得越早，prompt 控制力越弱、风格越抽象

典型用法：

  • 风格化：想降低文本对画面细节的控制、让模型更自由 → 调到 -20 左右。
  • 减少过拟合：长 prompt 出现"文字污染"时，截断到 -2 ~ -3 可减轻。
  • SDXL-refiner：官方工作流里常把 base 模型 CLIP 截到 -2，再送入 refiner。

三、结构控制（ControlNet）

6. 加载 ControlNet 模型

ControlNetLoader

把硬盘里的 ControlNet 权重文件读进内存，生成可被 ComfyUI 识别的模型句柄，供后续 Apply ControlNet 节点使用。作用是让扩散模型沿着给定的线条 / 姿态 / 深度去画。

7. ControlNet 预处理器

AV_ControlNetPreprocessor

先把普通图像处理成 ControlNet 能"看懂"的条件图（线稿、姿态、深度等），再送给 ControlNet 引导扩散模型按结构作画。

参数说明常用值 / 本项目取值
preprocessor具体算法，按控制目标换：出线条选 lineart / lineart_anime，出姿态选 openpose，做深度选 depthlineart_anime（二次元线稿）
sd_version模型版本：用 SD1.5 的 ControlNet 就留 sd15，接 SDXL 的 ControlNet 要改成 sdxl，否则尺寸不匹配报错sd15
resolution输出分辨率。原则是与后续扩散步骤的 latent 分辨率接近，避免过大爆显存512（短边缩到 512，另一边自适应）
preprocessor_override手动覆盖配置None（99% 时间保持默认）

8. 应用 ControlNet

ControlNetApplyAdvanced

把"条件图"和"文本 prompt"一起注入扩散模型：让生成结果遵循结构控制，同时保留 prompt 的风格描述。真正需要调的只有三个滑条。

参数含义常用范围调参提示
强度（Strength）条件图影响力0.5 – 1.31.0 最常用；< 1 更自由，> 1 更严格，过高会崩坏
开始百分比从总步数的百分之几开始介入0.0 – 0.20.0 = 一开始就控制；想先让 prompt 起稿、后阶段再按结构修正可设 0.2 – 0.3
结束百分比到总步数的百分之几停止介入0.8 – 1.01.0 = 全程控制；< 1 会在最后几步放开，让细节更柔和

三个滑条的调节逻辑：

  • 强度：0.6 以下结构松散、更听 prompt 的话，适合"大致姿势参考"；1.0 是平衡点；1.2 – 1.3 线条 / 姿态几乎像素级还原，但容易出伪影。
  • 开始百分比：0.0 一开始就介入、结构最稳；0.2 – 0.3 先让 prompt 做"草图"、中后期再用条件图矫正，可减少生硬感；0.5 以上只在最后微调，效果较弱。
  • 结束百分比：1.0 全程控制；0.7 – 0.9 最后几步放开、让模型自由细化纹理，减少"贴图感"；0.5 以下基本只剩 prompt 控制。

四、输出

9. 合并为视频

VHS_VideoCombine

把一批帧序列重新封装成视频输出。关键参数与取值口径：

参数说明推荐值
帧率（fps）输出视频帧率8 – 30（AnimateDiff 常见 8 / 12 / 16）
循环次数GIF 专用，0 = 无限循环0
文件名前缀输出文件名前缀video → video_00001.mp4
格式容器 + 编码组合video/h264-mp4（兼容性最好）
pix_fmt像素格式yuv420p（通用）
crf视频质量，值越小画质越高、文件越大19（视觉无损）
保存元数据把 ComfyUI 元信息写进文件true
修剪音频音频长度自动对齐视频false（通常让音频保持原长）
Ping-Pong正向播完再反向播，做循环 GIF 用false

五、为什么这些默认值要写下来

这套工作流要交给设计和剪辑同事复跑，所以每个节点的关键参数都固化成默认值：同事只需要选项目、上传文件夹、选"男性年轻化 / 女性年轻化"这类美化参数就能出结果， 不需要理解 CLIP 层数或 ControlNet 强度。调参口径集中在这里维护，避免每个人各调一套、结果不可复现。
